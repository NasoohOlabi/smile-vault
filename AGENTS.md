# AGENTS.md

Guidance for AI coding agents working in this repo.

## What this is
Smile Vault is the front-end for the Dama store — plain HTML/JS, styled with Tailwind via Vite.
- Dev: `bun run dev` → http://localhost:5173 (HMR)
- Prod build: `bun run build` → `dist/` (Firebase Hosting / static upload)
- Legacy static URLs: https://nasooholabi.github.io/smile-vault/ · https://dama-store.wuaze.com/?i=2

## File layout
- `index.html` — storefront shell. `src/app.js` depends on its IDs; don't change markup structure casually.
- `src/main.js` — Vite entry (CSS + Firebase + app).
- `src/input.css` — Tailwind theme + component layer (Kiosk Screen).
- `src/app.js` — cart, filters, lightbox, checkout, views.
- `src/firebase.js` — Firebase app + Analytics init.
- `src/analytics.js` — GA4 helpers (`track`, ecommerce items, SPA `page_view`).
- `catalog/shop/` — **source of truth** for shop tabs + product lists (YAML). Folders = tabs; leaf `items.yaml` = products. Optional `_meta.yaml` for labels / feature blocks.
- `products.json` + `catalog-nav.json` — generated by `bun run catalog` (`bun s.js`); served in dev/build via `vite.config.js` catalog plugin.
- Image folders at repo root (`Stickers/`, `Tshirts/`, …) — referenced by YAML `image` paths; not moved into `catalog/`.
- `assets/*.png` — brand images (logo, sun, stamp).
- `s.js` — catalog generator (`bun run catalog`).

## Theming
Kiosk tokens live in `@theme` inside `src/input.css`. JS state variants (`is-open`, `is-active`, …) are declared with `@custom-variant`. Markup uses Tailwind utilities only (plus small pattern utilities `bg-checker`, `bg-checker-dark`, `scrollbar-none`). Vite HMR updates CSS when you edit `src/input.css` or class strings.

## Commands
```bash
bun install
bun run catalog # rebuild products.json + catalog-nav.json from catalog/shop/
bun run dev     # Vite + Tailwind HMR
bun run build   # output dist/
bun run preview # preview production build
```

## Conventions
- English only, LTR. UI copy lives in `index.html`; shop tab labels live in `catalog/shop/**/_meta.yaml` (via `catalog-nav.json`).
- Edit products in leaf `items.yaml` files; do not hand-edit `products.json` unless regenerating immediately after.
- **Price** (optional overwrite, most-specific wins):
  1. File default: top-level `price: 350`
  2. Item overwrite: `price:` on the product
  3. Variant overwrite (tees): `price:` on a `variants[]` entry

```yaml
price: 350
items:
  - title: Local Product
    price: 400          # item overwrite
    image: Tshirts/LocalProduct.jpg

  - title: Map
    price: 375          # default for all Map colors
    variants:
      - color: B
        front: Tshirts/Map_B_F.jpg
        back: Tshirts/Map_B.jpg
      - color: W
        price: 425      # variant overwrite
        default: true
        front: Tshirts/Map_W_F.jpg
        back: Tshirts/Map_W.jpg
```

- Tshirts may use a `variants` array instead of a single `image`:

```yaml
- title: Map
  variants:
    - color: B          # B black · W white · BL blue
      front: Tshirts/Map_B_F.jpg
      back: Tshirts/Map_B.jpg
    - color: W
      default: true       # card / lightbox start on this color
      defaultSide: front  # optional: front | back
      front: Tshirts/Map_W_F.jpg
      back: Tshirts/Map_W.jpg
```

  Or set `defaultColor: W` (and optional `defaultSide`) on the item itself. Single-image tees still use `image:`. After edits run `bun run catalog` (or `scripts/rebuild-catalog.ps1` if needed).

- Order destination: `SHEETDB_URL` in `src/app.js`.
- Cart: `localStorage` key `dama_cart_v2` (+ legacy `p_<id>` migration).
- Analytics: GA4 via Firebase (`G-J557MTRP00`). Ecommerce currency **SYP**. Funnel events live in `src/app.js` (`view_item_list` → `select_item` / `view_item` → `add_to_cart` → `view_cart` → `begin_checkout` → `purchase`). SPA `page_view` fires on hash/title changes. Local DebugView: append `?debug_mode=1` to the URL. In the GA4 console, mark **`purchase`** as a key event (conversion) to get conversion rate.

## Testing
Golden path in the Vite dev server: browse catalog, lightbox, cart, checkout validation. With `?debug_mode=1`, confirm events in GA4 DebugView.
